# 자동 트레이딩 시스템 — 설계 v2 (1차: 규칙 연구실)

작성일: 2026-11-19 · 상태: v2.1 (검토 반영 + 3차 조사 적용, 사용자 승인 대기)
근거 조사: `research/2026-11-19-prior-art.md` (1·2차)

## 1. 왜 만드나

토스증권 일반 계좌로 국내·미국 주식을 **단타와 스윙 두 주머니**로 나눠 자동 운용한다.

1. **실제 수익** — 최종적으로 실계좌에서 돈을 번다.
2. **블로그 소재** — 규칙을 찾고 검증하고 운용하는 과정을 공부·IT 네이버 블로그 연재로 쓴다.
3. **들여다보는 시간 줄이기** — "어떤 종목에 들어갔고, 수익이 어떻게 됐는지"를 대시보드 한 화면으로 본다.

출발 자료: quantframe 오픈소스 헤지펀드 스택(Kronos·skfolio·NautilusTrader·Vibe-Trading), TradingAgents, ai-hedge-fund(월가 5인). 이 자료들은 일·분기 단위라 **스윙에서 주로 쓰이고**, 단타에는 틀(검증·리스크·역할 분리)만 가져온다.

**보류:** ISA 장기 주머니. (토스에 자체 ISA 없음 → 키움·한투 API 필요, ISA는 미국 주식 직접 불가, 국내 주식 단타엔 ISA 이점 거의 없음. 조사 문서 참고.)

## 2. 전체 그림

|---|---|---|---|---|---|
| 단타 | 국내 / 미국 | 토스 1분봉 | 당일 청산 | 5만 / 5만 원 | 500만 / 500만 원 |
| 스윙 | 국내 / 미국 | 토스 일봉 (+1분봉 체결 모사) | 2~20거래일 | 5만 / 5만 원 | 500만 / 500만 원 |

(국내·미국 반반 배분은 설계자 판단, 사용자가 바꿀 수 있음.)

작업 순서:

| # | 작업 | 이번 문서 범위 |
|---|---|---|
| ① | **규칙 연구실** — 후보 규칙을 비용 포함 백테스트로 걸러 검증. **스윙 먼저, 단타 이어서.** | **상세** |
| ② | **자동매매 엔진** — 토스 연결, 가상 체결 모의 운용 → 소액 실거래 | 인터페이스와 반드시 반영할 교훈만 |
| ③ | **대시보드 + 블로그** — 주머니별 현황 한 화면, 블로그 초안 | 산출물 형식만 |

최종 운용 흐름:

```

[장중]        결정론적 규칙 코드: 신호 → 확신도 기반 크기 → 리스크 한도 → 주문
[대시보드]    주머니(단타/스윙) × 시장(국내/미국)별 보유, 당일·누적 손익, 규칙별 성적
```

## 3. 목표 · 비목표 · 반목표

**목표 (①)**
- 스윙·단타 후보 규칙을 국내·미국 데이터로 빠르게 걸러, **토스 실제 비용(수수료·세금·호가단위·슬리피지)을 빼고도 통계적으로 남는 규칙**만 추린다.
- 추린 규칙을 NautilusTrader로 옮겨 정밀 재검증하고, 그 코드가 ②의 모의·실거래 코드가 되게 한다.
- 시도한 모든 후보와 결과를 기록해 블로그 원고 재료로 남긴다. **탈락 기록도 산출물이다.**

**비목표**
- 실거래 주문, 실시간 운용, 대시보드 UI (② ③)
- ISA·장기 주머니 (보류)
- 초단타·호가 스캘핑 (토스 어뷰징 제한)
- 미국 프리·애프터, 국내 NXT·애프터마켓 (1차는 정규장만)

**반목표 (돌아가도 실패인 것)**
- LLM이 주문 경로에 들어가는 것. (Alpha Arena: 실돈 LLM −30~−63%)
- 백테스트에만 맞춘 규칙 통과. (Quantopian 교훈)
- 모의 운용 기준 통과 전 실돈 투입.
- 토스 API 데이터의 제3자 배포. 블로그에는 원시 시세·차트를 싣지 않고 내 성적·과정·규칙 설명만. 데이터 파일은 저장소에 커밋하지 않는다.

## 4. 제약

### 4.1 토스 Open API (공식 명세·FAQ 직접 확인, 2026-11-19)
- 호스트 `https://openapi.tossinvest.com`, WebSocket `wss://openapi-ws.tossinvest.com/ws/v1` (채널 `trade:{kr|us}`, `orderbook:{kr|us}`, `personal:order`; 계정당 연결 2, 연결당 구독 100).
- **캔들:** `GET /api/v1/candles` — `interval` = `1m` | `1d`, `count` ≤ 200, `before`(이전 응답 `nextBefore`)로 과거 페이지네이션, `adjusted`(기본 true). 최신순 정렬. **1분봉은 국내 2022-11-23~, 미국 2021-12-01~. 일봉은 기간 제한 없음.**
- 1분봉 타임스탬프는 **봉 종료 시각**. 국내는 KRX+NXT 통합 시세(08:01~20:00).
- **상장폐지 종목 조회 불가(404)** → 생존 편향 회피 불가. **미국 시세는 일부 거래소 기준, NBBO 아님.**
- **랭킹(`/rankings`)·종목 목록(`/stocks/all`)·유의사항(`/stocks/{symbol}/warnings`)은 현재값만.** 과거 유니버스는 우리가 일봉으로 계산.
- **재무제표 API 없음.**
- 주문: 국내·미국 지정가/시장가, 정정·취소. 국내는 같은 종목 반대 방향 미체결 주문 있으면 409.
- **조건주문:** `SINGLE`/`OCO`/`OTO`. **OCO는 매도·지정가만** (손절도 지정가 → 급락·갭 미체결 위험). **국내 조건주문은 KRX 정규장에서만 발동**, 미국은 전 세션.
- **미국 소수점:** 매수는 금액 주문만, 소수점 수량은 시장가 매도만, 둘 다 **정규장 시작~마감 1시간 전까지만**. → 소수점 포지션엔 서버 OCO 손절 불가.
- 미국 주문 자동환전 없음 (달러 미리 환전).
- `clientOrderId` 멱등 10분. 체결 건별 REST 없음 → 웹소켓 `personal:order`.
- 호출 한도(초당): MARKET_DATA_CHART 20, MARKET_DATA 15, ORDER 10, ORDER_INFO 6(09:00~09:10은 3), ACCOUNT 1, RANKING 5, STOCK 5.
- 인증 OAuth2 client credentials, **클라이언트당 유효 토큰 1개** → 토큰 쓰는 프로세스 하나.
- **허용 IP 필수** (현재: 키 발급됨, IP 미등록). ① 수집은 이 맥의 공인 IP 등록으로 시작(설계자 판단).
- 소액 주문 수백 건 반복 시 어뷰징으로 매매 제한.
- 수수료율: `GET /api/v1/commissions`의 `commissionRate`(소수 비율)로 조회.

### 4.2 시장 구조
- 국내 정규장 09:00~15:30, **15:20~15:30 장 마감 동시호가** → 연속매매 청산은 15:20 전.
- **국내 VI:** 정적 ±10%(기준가 대비), 동적 코스피200 3% / 그 외 6%(직전 체결가 대비), 발동 시 **2분 단일가**. 횟수 제한 없음.
- **국내 호가단위:** 2,000~5,000원 5원, 5,000~20,000원 10원, 20,000~50,000원 50원 (그 외 구간은 KRX 표 그대로 설정 파일에).
- 미국 정규장 23:30~06:00 KST (서머타임 22:30~05:00).

### 4.3 비용 (설정 파일, 공식 값으로 채움)
- 국내: 매도 시 증권거래세 **0.20%** + 토스 수수료(API 조회) + 슬리피지(기본 1호가).
- 미국: 토스 수수료(블로그상 0.1%/편도, API 조회로 확정) + 매도 SEC fee 0.00206% + 슬리피지(보수적).
- **비용(R) = 왕복 비용% ÷ 손절폭%** 를 모든 후보에 계산. 단타 연구의 핵심 지표.

### 4.4 실행 환경
- 이 맥 시스템 python3는 Xcode 라이선스 미동의로 막힘 → `uv`로 Python 3.12.
- NautilusTrader 1.231.x(마지막 안정 1.x) 고정. 2.0은 rc 단계라 1차에서 쓰지 않음(설계자 판단).
- vectorbt 오픈소스판.
- 비밀값은 `.env`(커밋 제외)·환경변수만. 채팅·코드·로그 금지.

## 5. 자본과 리스크 (사용자 결정 + 설계자 판단)

**사용자 결정:** 실제 단타 10만 원, 스윙 10만 원. 모의 단타 1,000만 원, 스윙 1,000만 원. 거래당 위험 1%. 일일 손실 3% 도달 시 해당 주머니 당일 정지.

**설계자 판단:**
- 각 주머니 국내 50% / 미국 50%.
- 종목당 최대 비중 25%.
- 스윙 추가 한도: 동시 보유 최대 4종목(25% 상한과 일치), 주머니 고점 대비 -15% 낙폭 시 신규 진입 중단.
- **종목 교체형 규칙의 동일 비중 (2026-11-23 사용자 결정):** 모멘텀·ETF 갈아타기처럼 정기 교체하는 규칙은 거래당 위험 1% 대신 (전일 종가 평가 자본 ÷ 보유 칸 수)로 산다. 개별 종목은 종목당 25% 상한 유지, ETF 갈아타기는 ETF 하나에 100%까지. 현금이 모자라면 남은 현금만큼만 산다. 일일 -3%·낙폭 -15% 정지는 그대로. 손절로 끊는 규칙은 거래당 위험 1% 유지 (2% 상향은 사용자가 보류). 이유: 위험 기준 배분은 손절폭이 넓은 교체형에서 자본의 7%만 쓰여, 지수 보유와 비교 자체가 안 됐다.
- 스윙 손절은 **갭 위험 포함**해 크기 계산: 위험 금액 = 수량 × (진입가 − 손절가) + 갭 여유(해당 종목 과거 시가 갭 분포의 95% 분위수). 갭으로 손절가 아래 체결되는 것을 백테스트에 그대로 반영.
- **두 자본 시나리오를 항상 같이 평가:** 실제(시장당 5만 원)와 모의(시장당 500만 원). 5만 원 시나리오는 정수 주 반올림, 국내 1주 가격 상한(포지션 상한 1만 2,500원), 미국 소수점 제약(금액 매수·마감 1시간 전 청산·서버 손절 불가)을 반영. **같은 규칙이 5만 원에선 안 되고 500만 원에선 되는 경우를 리포트에 분리 표기.**

### 7.2 데이터
- 수집: 일봉(전 종목, 가능한 최장) → 1분봉(유니버스 후보 종목, 1분봉 제공 기간 전체). 야간 일괄.
- 저장: `data/{market}/{interval}/{symbol}/{yyyy-mm}.parquet` (일봉은 종목당 1파일도 가능).
- 정합성 검사: 결측·중복·타임스탬프 역행·음수·OHLC 모순.
- **반드시 테스트할 함정:** 봉 종료 타임스탬프(신호는 봉이 끝난 뒤에만 사용), 국내 통합 시세에서 정규장 09:00~15:30만 자르기, 수정주가.
- **고정 한계 (모든 리포트 자동 표기):** 상장폐지 제외로 인한 생존 편향, 미국 NBBO 아님, 과거 거래정지·유의종목 이력 없음.
- (선택) 미국 교차검증: Alpaca 무료 SIP 분봉과 표본 비교.
- **스윙 기간과 생존 편향 (설계자 판단):** 스윙 백테스트는 **2016-01-01 이후**로 제한(수십 년치를 쓰면 생존 편향이 커짐). "유료는 사용자 결정"은 무료 보조 소스를 막지 않는다 → **국내 상장폐지 종목 일봉은 pykrx/FinanceDataReader 등 무료 소스로 보충**(개인 사용 조건 확인). 미국 상장폐지 보충은 무료로 가능한 범위만(Alpaca 등) 시도하고, 못 하면 고정 한계로 표기. 리포트에 "상폐 보충 여부"를 시장별로 표시.

### 7.3 유니버스 (일봉으로 매일 재계산)
- 공통: 현재 상장 종목(`/stocks/all`) 중 해당일 기준 직전 20일 평균 거래대금 상위 N(기본 200).
- **ETF (사용자 결정):** 국내·미국 **일반 ETF 포함**, 레버리지·인버스 ETF 제외. **국내 ETF는 증권거래세 없음** → 비용 설정을 개별주와 분리(`costs`에 상품 유형별 요율). ETF 호가단위(저가 ETF 1원 호가 → 1% 안팎 흔들림)도 호가단위 비용 조건에 포함. 지수 ETF(KODEX 200, TIGER 200, SPY, QQQ 등)는 거래대금 순위와 무관하게 항상 포함.
- **제외 (설계자 판단):** 우선주, 스팩, ETN.
- 국내: **호가단위 비용(1호가 ÷ 주가) ≤ 0.1%**, 자본 시나리오별 1주 가격 상한.
- 미국: 시가 > $5, 14일 평균 거래량 ≥ 100만 주.

### 7.4 후보 규칙 — 스윙 (먼저)
1. **추세 돌파:** N일 고점 돌파 진입, M일 저점 또는 ATR 배수 이탈 청산 (N, M 격자).
2. **이동평균 추세:** 단기·장기 이동평균 정배열 + 눌림 진입.
3. **단기 과매도 되돌림:** 상승 추세 종목의 2~5일 급락 후 반등 (예: RSI(2), 종가 위치 지표).
4. **모멘텀 순위:** 직전 1~3개월 수익률 상위 종목을 주기적으로 교체 (회전율 상한).
5. **Kronos 일봉:** 경로 샘플 평균(방향)·표준편차(확신도). CPU 소규모 측정부터.
6. **단기 반전 (국내 우선):** 최근 5~20일 하락률 상위 종목 매수(유동성 필터). 한국은 단기 모멘텀보다 반전이 더 자주 확인됨 → 국내 모멘텀 규칙(4)은 기대치 낮춤.
7. **오버나이트 보유:** 국내 ETF 종가 매수 → 다음 날 시가 매도 (1박). ETF 수익은 오버나이트 양(+)·장중 음(-)이 보편적. 거래세 없는 국내 ETF에서만 의미.
8. **월바뀜(TOM):** 월말 N일 전 매수 → 월초 M일 후 매도 (지수 ETF·코스닥).
9. **ETF 갈아타기 (듀얼 모멘텀, 2026-11-23 추가):** 유니버스 안 ETF(레버리지·인버스 제외)를 63/126/252일 수익률로 순위 매겨 10/20 거래일마다 상위 1~3개 보유, 수익률이 0 이하면 그 칸은 현금(절대 모멘텀). ATR 3배 손절은 폭락 대비용. 동일 비중.
- **월가 5인 재무 점검은 연구실 검증 대상이 아님** (토스에 재무 API 없고, 과거 시점 재무 데이터 없이는 백테스트 불가). ② 운용 단계의 보조 필터 후보로 남긴다.
- 공통: 롱 위주, 진입은 다음 날 시가 또는 장중 1분봉 조건, 손절·익절·최대 보유일 청산.

- 규칙별 신호 강도를 0~1로 정규화해 확신도로 출력(예: 돌파폭÷ATR, 거래량 배수, 이격도÷변동성, Kronos 표준편차 역수). 규칙 카드에 산식 기록.
- 1차 거르기: 고정 금액. 2차 이후·통과 판정: 확신도 크기 + 실제 자본 시나리오.

### 7.8 검증 절차
1. 주머니 × 시장별로 기간 분할: 학습 60% / 검증 20% / **봉인 20%**. 스윙은 일봉 전체 기간, 단타는 1분봉 제공 기간.
2. 1차 거르기(vectorbt, 학습): 비용 포함 순수익.
3. 2차(검증 기간): 워크포워드. PBO(CSCV) 계산.
   - **봉인 추천 조건 (2026-11-23 추가):** 검증 기간 순수익 > 0 **그리고** 검증 기간 수익률(순수익 ÷ 모의 자본)이 같은 기간 기준 지수 단순 보유 수익률(국내 069500 KODEX 200, 미국 SPY; 비용 없이 계산)보다 높을 것. 지수만 사서 들고 있는 것보다 못한 규칙은 운용할 이유가 없다. 첫 실데이터 검증에서 미국 추천 3개가 +2~12%로 SPY +48.9%에 크게 못 미쳐 추가.
4. 3차(NautilusTrader, 봉인 1회): 최종 후보만.
5. **통과 기준 (봉인 표본, `lab.yaml`):**
   - 거래당 순 R 평균의 t ≥ 2
   - Deflated Sharpe Ratio ≥ 0.95 (시도한 후보 수 반영)
   - PBO ≤ 0.5
   - 수익 상위 5거래 제외해도 순수익 양수
   - Profit Factor ≥ 1.2, MDD ≤ 15%
   - 검증·봉인 모두 순수익 양수
   - 거래 수 ≥ 100 (최소 요건일 뿐)
6. **코드로 강제:** 모든 실행은 후보 수와 함께 실험 기록에 자동 적재. 봉인 표본은 `lab verify --final`만 읽을 수 있고, 규칙별로 한 번 열면 잠금 기록.
   - **봉인을 열 수 있는 최종 후보는 주머니 × 시장당 최대 3개** (설계자 판단). 초과 시 명령 거부.
   - **DSR 시도 횟수 = 해당 주머니 × 시장에서 실행한 모든 파라미터 조합 수** (가장 보수적, 실험 기록에서 자동 집계).
   - **자본 시나리오별 판정 (설계자 판단):** 봉인은 규칙당 한 번 열고 그때 두 시나리오를 함께 계산. **모의 500만 원 시나리오 통과 → ② 모의 운용 진행 자격.** 실돈 5만 원 투입은 5만 원 시나리오도 통과해야 하며, 못 하면 실돈 전환 시점에 자본 증액 여부를 사용자가 결정.
7. 운영: 완전 자동 루프 없음. CLI(`lab collect`, `lab universe`, `lab screen`, `lab validate`, `lab verify`, `lab report`)를 사용자가 Claude Code 세션에서 함께 돌림.

### 7.9 탈락 시 경로 (사용자 결정)
- **②는 스윙·단타 연구가 모두 끝난 뒤 시작한다** (사용자 결정). 그 시점에 주머니 × 시장 중 **하나라도 통과했으면 ②로 진행** (통과한 것만 운용).
- 전부 탈락하면 새 데이터 3개월 쌓인 뒤 새 봉인 표본으로 재검증, 그동안 ② 엔진을 먼저 만든다. 탈락한 봉인 표본으로 다시 고르지 않는다.
  - **재검증 봉인 정의 (설계자 판단):** 새 봉인 = 직전 봉인 종료 이후 쌓인 데이터 전체. 재검증은 **최소 3개월 + 통과 기준의 최소 거래 수(≥100)를 채울 만큼 데이터가 쌓였을 때** 연다. 기준 자체는 낮추지 않는다. 재검증 대상은 직전 최종 후보(최대 3개)만.
- **①의 완료 기준:** 통과 규칙 ≥ 1개 + 규칙 카드, 또는 전원 탈락 기록 + 재검증 일정.
